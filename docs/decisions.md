# Решения

Решения, принятые при реализации MVP: ответы на открытые вопросы из [spec.md](spec.md) и технический выбор. Если решение нужно поменять — меняйте здесь и в коде.

## Открытые вопросы спеки

| Вопрос                             | Решение                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Поиск по параметрам                | Один поисковый запрос без фильтров: подстрока без учёта регистра по своему названию вещи, названию типа, ключам и значениям параметров (строки, URL, числа, варианты enum, названия вещей и типов в ссылках). Запрос вида `ключ: значение` ищет параметр с этим ключом и значением. Нечёткого поиска и словоформ в MVP нет — для каталога до ~10 000 вещей хватает `ILIKE` в PostgreSQL. |

## Модель данных

- Рабочий стол — строка `Item` с `isWorkbench = true`, без типа (`typeId` пустой только у столов — проверяется CHECK-ограничением), всегда на верхнем уровне. В поиске и обычных списках столы не показываются, в путях — как «Рабочий стол Гараж».
- Вещь «на столе», пока заполнено `takenById`; `homeId` — контейнер, откуда её взяли (пусто, если с верхнего уровня).
- Вещь в архиве сохраняет `parentId`, чтобы восстановление вернуло её на место (если место ещё активно; иначе — на верхний уровень).
- При архивации наклейка списывается, но остаётся связанной с вещью, чтобы восстановление привязало её обратно. Отвязанная вручную (испорченная) наклейка списывается и отвязывается.
- «Личное или общее — ровно одно из двух» (`ownerId` / `householdId`) и «параметр принадлежит типу или вещи» закреплены CHECK-ограничениями в миграции. Все запросы сервисов фильтруются через `visibleTo(actor)`, поэтому домохозяйства добавятся без переписывания запросов.
- Варианты enum хранятся по id (`ParamEnumValue`), поэтому переименование варианта видно везде.

## Технический выбор

- **Prisma 6** (а не 7/8): стабильный классический генератор клиента без отдельных драйвер-адаптеров.
- **Пароли** — argon2id (`@node-rs/argon2`, параметры OWASP). **Сессии** — случайный токен в httpOnly-cookie (SameSite=Lax), в БД хранится только его SHA-256; срок 30 дней с продлением.
- **API**: все изменения идут через JSON API `/api/*` (задел на офлайн), страницы читают данные на сервере через тот же слой сервисов.
- **Файлы** отдаются приложением (`/files/<key>`) после проверки входа и владения; MinIO наружу не выставляется.
- **Шрифты PDF** — DejaVu Sans / Sans Mono (лицензия в `assets/fonts`), чтобы кириллица в подписях печаталась.
- **Хранилище без `S3_ENDPOINT`** — в памяти, только для разработки; в образе нужно задавать MinIO.

## Поведение, уточнённое при реализации

- **Наклейки.** В PDF до 20 листов за раз. Подпись хранится полностью и обрезается до 16 символов только при печати. В QR — URL целиком заглавными (алфавитно-цифровой режим), поэтому в `QR_BASE_URL` не должно быть `_`. Подсказка «Возможно, …?» ищет только среди своих наклеек.
- **Создание вещи.** Если введённое имя типа совпадает с существующим (без учёта регистра), используется существующий тип.
- **Поиск.** Сначала тип с точным совпадением названия, затем по алфавиту. Параметр типа, перекрытый параметром вещи, в поиске не участвует. Не больше 500 найденных записей.
- **Формат значений.** Числа — с запятой и узким пробелом в тысячах («4 500 ₽», «4,5–16 В»), даты — «1 мая 2027».
- **Рабочий стол.** Часть количества вливается обратно в исходную запись, только если та активна, лежит на прежнем месте и у части не появилось своей наклейки или содержимого; иначе часть возвращается отдельной записью. Перемещение между столами сохраняет исходное место. «Использовать» всё количество отправляет запись в архив с последним количеством, чтобы восстановление вернуло его.
- **Архив.** Вещи, выкинутые одной операцией, восстанавливаются вместе. Если контейнер лежал прямо на столе, его содержимое по умолчанию остаётся на этом столе. Окончательное удаление переносит активное содержимое на верхний уровень, а наклейку оставляет списанной.
- **Файлы.** Небезопасные типы (не изображения, PDF и текст) отдаются как скачивание с `nosniff` и `CSP: sandbox`. Загруженный, но не сохранённый в параметр файл остаётся в хранилище (очистки пока нет).
- **Пароль.** Смена пароля завершает все остальные сессии пользователя. Cookie сессии ставится с `Secure` (кроме localhost) — приложение должно работать за HTTPS-прокси.
- **Старт.** Создание бакета повторяется с нарастающей паузой, если MinIO ещё не поднялся.
- **MinIO в docker-compose и CI** — образ `bitnamilegacy/minio` с фиксированной версией: официальный `minio/minio` больше не публикуется в Docker Hub. В продакшене можно использовать любой S3-совместимый MinIO.

## После MVP (ревью, 2026-10-10)

- **Интерфейс** — на [Flowbite Svelte](https://flowbite-svelte.com/) (Tailwind CSS 4, иконки `flowbite-svelte-icons`). Свой CSS только в `src/app.css`: подключение Tailwind и Flowbite, основной цвет, базовые стили. Тёмная тема — по системной настройке. Пакеты UI — в `devDependencies`: Vite собирает их в бандл, в образ они не попадают.
- **Навигация.** На телефоне — нижняя панель (Поиск, Скан, Стол, Контейнеры, Ещё); «Ещё» открывает шторку с наклейками, типами, параметрами, архивом, профилем и выходом. С ширины `md` — верхняя панель со всеми разделами.
- **Контейнер — флажок вещи** (`Item.isContainer`, «Это контейнер»). Класть внутрь (создание, «Переложить», «Положить в другое место») можно только в контейнер; рабочий стол — всегда контейнер. Миграция отметила контейнерами всё, во что уже что-то клали или откуда что-то доставали. Снять флажок нельзя, пока внутри лежат активные вещи или вещи из него лежат на рабочем столе. Если при восстановлении из архива прежнее место больше не контейнер, вещь встаёт на верхний уровень; «Вернуть на место» в такой контейнер недоступно. У не-контейнера в карточке нет блока «Содержимое», а в выборе места — его нет среди вариантов.
- **Вкладка «Контейнеры»** (`/containers`, бывшая «Вещи», старый адрес `/items` перенаправляет): верхний уровень, сначала контейнеры, ниже — «Вещи без места». В содержимом контейнера контейнеры тоже идут первыми.
- ~~**Фото вещи**~~ (заменено во второй порции: фото теперь только у типа) — одно своё фото у вещи (`Item.photoKey`), в дополнение к фото типа (уточнение FR-3: «фото только у типа» больше не так). Хранится в MinIO как загружено, без обработки: принимаются JPEG, PNG, WebP и GIF (тип определяется по первым байтам), до 20 МБ, ключ `items/<id>/<uuid>.<ext>`. Новое фото заменяет старое; при окончательном удалении вещи фото удаляется. В списках и карточке показывается фото вещи, если его нет — фото типа. Фото можно добавить при создании вещи и в её карточке.

## Вторая порция замечаний (ревью, 2026-10-10)

- **Контейнер — всегда один экземпляр.** У контейнера и рабочего стола количество всегда 1 (CHECK `Item_container_single` в БД и проверка в `createItem`/`updateItem`). Миграция выставила 1 всем контейнерам с большим количеством. Отметить «Это контейнер» у записи с количеством больше 1 можно, только если вместе с отметкой передано количество 1. В формах поле «Количество» скрыто, пока отмечено «Это контейнер».
- **Часть количества во всех перемещениях.** «Переложить», «Положить сюда существующую», «Положить в другое место» и «Вернуть на место» принимают необязательное `quantity` (по умолчанию всё), как «На стол». Разделение записи одно на всех (`placePart` в `services/split.ts`): исходная запись сохраняет остаток, наклейку, свои параметры и место; переносимая часть — новая запись с тем же владельцем, типом и названием. Части, положенные через «Переложить», «Положить в другое место» и «Вернуть», не числятся на столе; остаток на столе остаётся на столе. Частичный возврат сливается с исходной записью по тем же правилам, что и полный, иначе становится новой записью в исходном месте. Поле «Сколько (из N)» показывается, только когда вещей больше одной.
- **Фото — только у типа.** `Item.photoKey` удалён; одно фото у типа, общее для всех его вещей; у рабочих столов фото нет. Миграция перенесла фото вещи на её тип, если у типа своего фото не было (при нескольких вещах — фото последней изменённой); остальные фото вещей больше нигде не показываются, а их файлы остались в хранилище. Фото меняется круглой иконкой поверх фото или заглушки: меню «Сфотографировать» (своя камера в приложении: снимок → «Переснять» / «Использовать», JPEG до 2048 px), «Выбрать файл» и, если фото есть, «Удалить фото». Без доступа к камере (HTTP, нет разрешения, нет камеры) показывается сообщение и «Выбрать файл». При создании вещи выбранное фото заменяет фото её типа. Загрузка — через фото типа (`PUT /api/types/:id/photo`, перекодирование в WebP, как раньше).
- **Параметры — отдельные сущности** (`ParamDef`: название, тип значения и для выбора из списка — выпадающий список). У типов и вещей хранятся значения (`Param.defId`), один параметр — не больше одного значения в типе или вещи. Название уникально у владельца без учёта регистра; переименование видно сразу везде. Тип значения и список можно поменять, только пока у параметра нет значений; удалить — тоже только неиспользуемый. Миграция создала параметры из старых ключей: один на ключ без учёта регистра; если один ключ использовался с разными типами значения или списками, самый частый вариант сохранил имя, остальные получили « (2)», « (3)». Единица измерения (у числа и диапазона) осталась у значения. Поиск «ключ: значение» ищет по названию параметра.
- **Страница «Параметры»** (`/params`, вместо «Справочников»): список всех параметров с типом значения и тем, где они заданы, создание нового; карточка параметра (`/params/:id`) — переименование, тип значения, где задан, удаление. На той же странице — раздел «Выпадающие списки» (бывшие справочники, `/params/lists/:id`); старые адреса `/dictionaries…` перенаправляют. Слово «справочник» в интерфейсе заменено на «выпадающий список»; в коде и API осталось `dictionary`.
- **Редактирование параметров на странице типа и вещи.** У каждой строки карандаш: значение правится на месте (там же ↑↓ и удаление), «+ Параметр» — найти существующий параметр или создать новый тут же, затем ввести значение. На карточке вещи значения типа помечены «· тип»; их правка меняет тип, если не отмечено «Только для этой вещи» (тогда создаётся своё значение вещи). Новый параметр на карточке вещи добавляется к вещи, с отметкой «Для всех вещей типа» — к типу. Списки параметров на страницах «Изменить» убраны; страница типа «Изменить» стала «Переименовать». API: `POST /api/{types|items}/:id/params`, `PUT|DELETE /api/params/:id`, `POST /api/params/:id/move`, `/api/param-defs`.
- **Даты везде по ISO**: «ГГГГ-ММ-ДД», с временем «ГГГГ-ММ-ДД ЧЧ:мм» по местному времени (`formatIsoDate`/`formatIsoDateTime` в `$lib/domain/dates`). Даты без времени разбираются как числа год/месяц/день, без `new Date('YYYY-MM-DD')`, чтобы не было сдвига на день.
- **Свой выбор даты** (`DateInput`): поле ГГГГ-ММ-ДД и календарь в стиле Flowbite, неделя с понедельника, названия по-русски, «Сегодня» / «Очистить». Ввод «ДД.ММ.ГГГГ» тоже принимается и сразу приводится к ISO. Datepicker из Flowbite не подошёл: подписи на английском, ячейки 32 px, стёртое поле не сбрасывает значение, ввод пробует американский формат.
- **Иконка стола** — ключ в `Item.icon` из списка `WORKBENCH_ICONS` (16 иконок flowbite-svelte-icons, `src/lib/domain/workbench-icons.ts`); `null` — иконка по умолчанию, как у пункта «Стол». Выбирается сеткой в настройках столов, показывается в списке столов, на странице «Рабочий стол» и при выборе стола в «На стол». Неизвестный ключ отклоняется.

## Третья порция замечаний (ревью, 2026-10-10)

- **Контейнер — свойство типа** (`ItemType.isContainer`, отметка «Контейнер» на странице «Изменить тип»); `Item.isContainer` удалён. Класть внутрь можно в вещи типа-контейнера и в рабочие столы (`isContainerItem` в `services/paths.ts`). Миграция отметила контейнером тип, у которого контейнером была хотя бы одна вещь (если у типа были и контейнеры, и нет — тип стал контейнером). Записи такого типа с количеством N > 1 разделены на N записей по 1: исходная сохранила место, наклейку и содержимое, копии получили то же место и копии своих параметров. Тип становится контейнером, только если у всех его вещей (в том числе в архиве) количество 1; перестаёт — только когда в его вещах ничего не лежит и ничего не взято на стол. При создании вещи нового типа отметка «Это контейнер» относится к новому типу; у выбранного существующего типа её нет — тип уже контейнер или нет. Смена типа вещи на тип-контейнер требует количества 1, на обычный — пустого контейнера.
- **Подтверждения — своё модальное окно** (`confirmAction` из `$lib/confirm.svelte.ts` + `ConfirmHost` в корневом layout) вместо `confirm()`/`alert()` браузера: удаление фото, параметра, типа, стола, окончательное удаление из архива, отвязка наклейки. Вопрос, необязательное пояснение, кнопка действия (по умолчанию красная «Удалить») и «Отмена»; Escape и клик мимо — отмена. С `cancelLabel: null` это уведомление с одной кнопкой.
- **Подписи «Фото общее для всех вещей типа» больше нет.**
- **Нельзя переложить вещь туда, где она уже лежит**: `moveItem` отклоняет («Вещь уже лежит здесь»), а выбор места не предлагает текущий контейнер; «Положить сюда существующую» не предлагает то, что уже лежит в этом контейнере.
- **Одинаковые вещи в одном месте — одна запись.** Когда при любом перемещении (переложить, на стол, вернуть, положить в другое место; целиком или частью) на месте назначения уже есть такая же запись, количество прибавляется к ней, а перенесённая целиком запись удаляется (`placePart` в `services/split.ts`). Такая же — тот же владелец, тип, своё название, место, состояние «на столе» (кто взял, откуда, от какой записи отделена) и одинаковые свои значения параметров; при этом ни у одной из двух нет наклейки, содержимого и ссылок из параметров «Вещь или тип», а тип — не контейнер. Отделённая часть теперь получает копии своих параметров исходной записи (раньше оставалась без них). Миграция по тем же правилам слила уже существующие дубли в каждом месте (кроме вещей на столе), оставив самую старую запись. При создании новой вещи записи не сливаются.
- **Раздел «Типы» переименован в «Типы вещей».**
- **Параметры на карточке вещи** — два списка: сначала «Индивидуальные параметры» (значения самой вещи), затем «Параметры» (значения типа, кроме тех, что переопределены значением вещи). Каждый список добавляет и правит свои значения; правка в «Параметрах» меняет тип, то есть все его вещи. Отметки «Для всех вещей типа», «Только для этой вещи» и пометка «· тип» убраны; чтобы у одной вещи значение отличалось, параметр добавляется в «Индивидуальные». `ItemCard.params` заменён на `itemParams` и `typeParams`.
- **Создание вещи существующего типа.** После выбора типа из подсказок поле заменяется карточкой типа (фото, название, отметка «контейнер», начало описания) с крестиком, который возвращает поле ввода. Если у типа уже есть фото, поля фото нет; если нет — фото можно добавить, оно станет фото типа. Так же выглядит выбор типа на странице «Изменить вещь».
- **Единица измерения — у параметра** (`ParamDef.unit`, поле на странице параметра и при создании, только для «Число» и «Диапазон»); `Param.unit` удалён, значение вводится без единицы, а показывается с единицей параметра. Миграция взяла самую частую единицу среди значений параметра (при равенстве — первую по алфавиту); значения с другой единицей теперь показываются с ней — их нужно поправить вручную. Единицу можно менять в любой момент, она сразу видна у всех значений.
- **Длинные файлы и ссылки сокращаются** (`$lib/domain/shorten.ts`): имя файла — начало, «…» и конец с расширением (32 символа), ссылка — без `https://`, начало с целым доменом и «…» (40 символов). Полное значение — во всплывающей подсказке и по ссылке.
- **Выпадающий список — часть параметра.** В интерфейсе осталась одна сущность «параметр»: у параметра типа «Выпадающий список» на его странице и при создании настраиваются варианты (добавить, переименовать, переставить, удалить неиспользуемый) и «Можно выбрать несколько вариантов». Раздел «Выпадающие списки», страницы `/params/lists/:id` и API `/api/dictionaries` убраны (старые адреса ведут на «Параметры»). В БД список остался таблицей `EnumDictionary`, но у каждого ENUM-параметра теперь свой (`ParamDef.dictionaryId` уникален), он создаётся и удаляется вместе с параметром. Миграция: список, общий для нескольких параметров, скопирован для всех, кроме самого старого (выбранные значения перенесены на копии вариантов); списки без параметров удалены; списки получили название своего параметра.
- **Описание типа** (`ItemType.description`, многострочное, до 2000 символов) задаётся на странице «Изменить тип» (бывшая «Переименовать»), показывается на странице типа, в карточке вещи, в списке типов и в карточке выбранного типа. Поиск находит вещи по описанию их типа; подсказки типов и фильтр в списке типов тоже ищут по описанию.

## Четвёртая порция замечаний (ревью, 2026-10-10)

- **Идентификаторы — cuid вместо UUID** в БД и адресах (`/items/cmv2qfe3d…`, 25 символов вместо 36). Колонки id и ссылок стали `TEXT`, новые записи получают `@default(cuid())` от Prisma; проверка во входных данных — `idSchema` из `$lib/domain/id`. Миграция `cuid_ids` выдала новый cuid каждой существующей записи (внешние ключи обновились каскадом `ON UPDATE CASCADE`), сессии сохранились — входить заново не нужно. Напечатанные наклейки не затронуты: в QR лежит адрес с кодом наклейки (`/K7M4QX`), а не id. Старые UUID не сохраняются (так решил Noah): сохранённые ссылки и закладки вида `/items/<uuid>` перестали открываться. Ключи файлов в хранилище не менялись (в них остались старые id, это просто имена).
- **Наклейка — всегда на одну вещь.** Привязка наклейки к записи с количеством N > 1 отделяет одну вещь в новую запись (то же место, состояние «на столе» и копии своих параметров, без слияния с такими же записями) и клеит наклейку на неё; у исходной записи остаётся N − 1, а карточка переходит на новую запись. `POST /api/stickers/bind` возвращает `{ itemId }` записи с наклейкой. Создать вещь с наклейкой и количеством больше 1 нельзя (в форме поле количества выключено с пояснением), изменить количество вещи с наклейкой тоже нельзя — поле в шторке «Изменить» выключено и объясняет почему; чтобы изменить количество, наклейку нужно отвязать. Миграция разделила уже существующие записи с наклейкой (в том числе списанной, но связанной с вещью в архиве) и количеством больше 1 так же.
- **Фото квадратные и в двух размерах.** При загрузке фото (после поворота по EXIF) вписывается в квадрат и дополняется прозрачными полями; хранятся два WebP с прозрачностью: крупный (до 2048 px, качество 88) по ключу фото и маленький (до 320 px, качество 75) рядом, `thumbKeyOf(key)` = `….thumb.webp`. Меньше исходного не увеличивается. Крупный показывается на странице типа и вещи (`PhotoField`), маленький — в миниатюрах (`Thumb`, `/files/<key>?size=thumb`). Уже загруженные фото не пересчитывались: у них маленького варианта нет, и вместо него отдаётся само фото. При замене и удалении фото удаляются оба варианта. В интерфейсе фото показывается в квадратной рамке (`PhotoField`, до 256 px), миниатюры и раньше были квадратными.
- **Нет отдельных страниц редактирования вещи и типа** (`/items/:id/edit` и `/types/:id/edit` удалены). Правки — на самих страницах по схеме «карандаш → шторка» (`Sheet`, `TextEditSheet`, `EditButton`):
  - карточка вещи: карандаш у названия открывает шторку со своим названием (пусто — показывается название типа); действия — группа кнопок с иконками «На стол», «Переложить», «Изменить». «Изменить» открывает шторку количества (`QuantitySheet`): поле с «−» и «+». Больше, чем сейчас, — «Сохранить»; меньше — «Использовать N шт.» / «Выкинуть N шт.» (обе уменьшают количество на N; истории нет, поэтому разницы между ними для данных нет); без изменения — «Использовать» / «Выкинуть» отправляют всю вещь в архив (для контейнера с содержимым «Выкинуть» сначала спрашивает, что делать с содержимым). У контейнера и вещи с наклейкой поле выключено с пояснением, остаются только «Использовать» и «Выкинуть». Отдельный блок «Использовать / выкинуть» внизу карточки убран.
  - **Тип у существующей вещи не меняется**: `PATCH /api/items/:id` принимает только `name` и `quantity`, поля типа игнорируются. Нужен другой тип — создаётся новая вещь.
  - страница типа: карандаши у названия и у описания открывают шторки; отметка «Контейнер» стоит прямо на странице и сохраняется сразу (если тип нельзя сделать контейнером или снять отметку, она возвращается и показывается причина). `PATCH /api/types/:id` принимает любые из полей `name`, `description`, `isContainer`.
- **Описание — над параметрами** и на странице типа, и в карточке вещи (в карточке вещи оно больше не стоит под названием).
- **У «Индивидуальных параметров» нет текста «Только у этой вещи параметров нет»** — пустой список показывает сразу кнопку «+ Параметр».

## Пятая порция замечаний (ревью, 2026-10-10)

- **Фото на странице вещи и типа — на всю ширину телефона** (с обычными полями страницы); на широком экране осталось до 256 px. В форме новой вещи фото по-прежнему небольшое (`PhotoField` с `wide`).
- **Описание типа — первые три строки**, остальное раскрывается по клику на текст или «Показать полностью» (компонент `Description`). Свернуть обратно нельзя — достаточно перезагрузки страницы. Карандаш стоит в конце текста; пока текст свёрнут, он рядом с «Показать полностью», чтобы править можно было без раскрытия.
- **Описание правится и с карточки вещи**: карандаш там же, шторка меняет описание типа (оно общее для всех вещей типа, о чём пишет подсказка). Без описания на карточке активной вещи показывается «Без описания» с карандашом.
- **Карандаш (`EditButton`) — в строке текста**: в конце названия и описания, серый, при наведении меняется только цвет (без серой плашки), рамка фокуса только с клавиатуры. Область нажатия 40 px выступает за строку и не раздвигает строки.
- **Кнопки действий на карточке вещи** на телефоне выше (64 px), иконка над подписью, во всю ширину. На странице типа «+ Вещь этого типа» оформлена так же и стоит сразу под фото; отметка «Контейнер» — под описанием, над параметрами.
- **Шторка «Ещё» — наша `Sheet`** с заголовком «Ещё» и своим крестиком: встроенный крестик `Drawer` оказывался под меню и не нажимался.
- **«Вернуть на место» на столе** открывает шторку: сколько положить и путь по шагам (каждый следующий контейнер с отступом, последний — жирным), кнопка «Готово» возвращает вещь. Пустой путь — «на верхний уровень».
- **Подпись поля названия** — «Название этой конкретной вещи» (в шторке и в форме новой вещи).
- **Список вещей на странице типа** озаглавлен «Всего N штук» (склонение — `plural` из `$lib/domain/plural`); в строке сначала название вещи (ссылка, жирное) и количество, под ним серым — путь. Если вещей нет, заголовка нет, только «Вещей этого типа нет» и «Удалить тип».
- **Нижняя панель на телефоне — своя разметка** вместо `BottomNav` из Flowbite: в тёмной теме у него были белые иконки при серых подписях и тёмно-синий активный пункт на сером фоне, а переопределить это классами не удавалось. Панель белая (в тёмной теме `gray-800`) с границей сверху. Обычный пункт серый; при наведении текст темнеет и за иконкой появляется серая «таблетка». Активный пункт — цвет `primary` (в тёмной теме светлый `primary-300`) на светлой синей таблетке (в тёмной — полупрозрачной `primary-900`); при наведении таблетка и текст становятся насыщеннее. Наведение срабатывает только на устройствах с курсором, после нажатия пальцем подсветка не залипает.
- **«Профиль» стал «Настройки»** (`/settings`, пункт «Настройки» в «Ещё»; ссылка с именем в шапке ведёт туда же). Адрес `/profile` убран без перенаправления. На странице: имя с карандашом (шторка, 1–100 символов, `PATCH /api/profile`), логин, выбор темы, пункт списка «Сменить пароль» (ListGroup) — он открывает отдельную страницу `/settings/password` с формой и ссылкой назад, — и «Выйти». Миграция не понадобилась: имя уже было в `User.name`.
- **Тема: светлая, тёмная или системная** — группа из трёх кнопок, по умолчанию «Системная». Тема хранится на устройстве (cookie `theme` на 400 дней), а не в аккаунте: на телефоне и компьютере удобно разное, и так не нужна миграция. Сервер подставляет её в `<html data-theme>` (и класс `dark` для тёмной), поэтому страница сразу рисуется в нужной теме; для «Системной» маленький скрипт в `app.html` ставит `dark` по настройке устройства до первой отрисовки и следит за её сменой. Вариант `dark:` в Tailwind теперь срабатывает от класса `dark` на `<html>` (`@custom-variant` в `app.css`), а не от `prefers-color-scheme`.
- **Камера снимает квадрат.** Превью своей камеры (`CameraCapture`) — квадрат, кадр обрезается по центру (`object-cover`), а не вписывается. Снимок — ровно этот квадрат (`centerSquare` из `$lib/domain/photo`, сторона до 2048 px), поэтому фото совпадает с превью и прозрачных полей у него нет. Фото из файла по-прежнему не обрезается, а дополняется до квадрата на сервере.
- **Серые бейджи в тёмной теме** (тип параметра, «N шт.», «в архиве», ссылки на странице параметра) получили фон `gray-700` и текст `gray-200`: у Flowbite фон серого бейджа `gray-900` совпадал с фоном страницы. Цветные бейджи («контейнер», «на столе») видны и так, их не трогали.
